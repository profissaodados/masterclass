Como um computador acha o que você quis dizer?

Imagine três amigos ajudando você a procurar um livro numa biblioteca gigante. O primeiro só acha o livro se você disser o título exato, mas é rapidíssimo. O segundo entende mesmo se você errar uma letrinha, tipo "Harry Poter". O terceiro é o mais esperto de todos: mesmo se você disser "aquele livro de bruxinho com óculos", ele entende o que você quer dizer e acha o livro certo. Esses três amigos existem de verdade dentro dos computadores — chamam-se Full-Text Search, Fuzzy Search e Busca Semântica. Nesta aula vamos abrir a cabeça dos três, com desenhos e demos que você mesmo controla.

Fundamentos
🔍 O problema da busca: computador não "entende" nada sozinho

Para nós, "gato" e "bichano" são quase a mesma coisa, e "gto" é obviamente um erro de digitação de "gato". Mas para um computador, no fundo, tudo isso são apenas sequências diferentes de letras. Cada uma das três técnicas desta aula resolve esse abismo de um jeito diferente — e cada uma tem seu superpoder e sua fraqueza. Vamos usar o mesmo cenário do início ao fim: um pequeno "zoológico" de frases sobre animais.

📖 Full-Text Search
Constrói um índice — tipo o índice remissivo no fim de um livro — que aponta direto para onde cada palavra aparece. Super rápido, mas só encontra a palavra exata (ou variações previstas, como plural).
🧩 Fuzzy Search
Mede o "quanto duas palavras se parecem" — quantas letrinhas você precisaria trocar para ir de uma até a outra. Perfeita para erros de digitação, mas não entende sinônimos.
🗺️ Busca Semântica
Transforma cada frase em um ponto num mapa do significado. Frases parecidas ficam perto uma da outra nesse mapa, mesmo usando palavras completamente diferentes.

💡 Nosso "corpus" de exemplo (8 frasezinhas) vai reaparecer em quase todas as demos de Full-Text e Fuzzy desta aula — assim dá pra ver a mesma base de dados sendo indexada, pontuada e filtrada de formas diferentes.

Full-Text Search · Passo 1
✂️ Tokenização: quebrando frases em pedacinhos

Antes de indexar qualquer coisa, o computador precisa cortar o texto em pedaços que ele consegue comparar — geralmente palavras, chamadas de tokens. É como separar um colar de miçangas: primeiro você tira cada conta do fio, depois pode organizá-las por cor. O pipeline típico tem 3 passos: separar, deixar minúsculo e remover palavras "vazias" (stopwords) que quase não ajudam a busca — "o", "a", "de", "para"...

E o "stemming"?

Motores de busca de verdade ainda fazem um passo extra: stemming/lematização, que reduz palavras à sua raiz — "gatos", "gatinho" e "gata" podem virar todos "gat". Assim, buscar "gato" também encontra frases com "gatos". Aqui simplificamos para focar no essencial: separar, normalizar e limpar.

Full-Text Search · Passo 2
📇 O índice invertido: o coração da busca full-text

Sem um índice, achar "gato" em 1 milhão de frases significaria ler todas elas, uma por uma. É exatamente o mesmo problema de achar um assunto num livro de 900 páginas sem índice remissivo. A solução é virar a tabela "de cabeça para baixo": em vez de frase → palavras, guardamos palavra → em quais frases ela aparece. Isso se chama índice invertido, e é o motivo pelo qual o Google devolve resultados em milissegundos.

Full-Text Search · Passo 3
🏆 Ranking: quem responde primeiro? (TF-IDF)

Achar os documentos certos é só metade do trabalho — o índice também precisa decidir a ordem de exibição. A ideia clássica se chama TF-IDF e tem uma lógica bem simples de criança: uma palavra é importante num documento se ela aparece muitas vezes ali (TF, frequência do termo) e ela não aparece em quase nenhum outro lugar (IDF, o quão rara/especial ela é no total). Palavra rara + repetida no documento certo = sinal forte.

🔢 TF — Term Frequency
Quantas vezes a palavra aparece naquele documento, dividido pelo total de palavras dele. Se "gato" aparece 1 vez numa frase de 4 palavras, TF = 1/4 = 0,25.
🌍 IDF — Inverse Document Frequency
O quão rara a palavra é no corpus inteiro. Se só 2 de 8 documentos têm "queijo", ela é bem mais "especial" que "gato", que aparece em metade dos documentos — IDF maior = palavra mais rara = mais peso.

Full-Text Search · Combinando termos
🔵 Busca booleana: AND, OR e NOT

Buscas raramente têm uma palavra só. Motores de busca combinam listas de postings com operações de conjunto — exatamente como um diagrama de Venn da escola. AND = interseção (está nos dois círculos). OR = união (está em pelo menos um). NOT = diferença (está num, mas não no outro).

Fuzzy Search
🤔 E quando alguém erra a digitação?

O índice invertido é rapidíssimo, mas é também um "chatinho de carteirinha": se você buscar "cachoro" (faltou um "r"), ele simplesmente não encontra nada — porque "cachoro" e "cachorro" são, para ele, duas sequências de letras totalmente diferentes. Humanos digitam errado o tempo todo (celular, pressa, distração). É aqui que entra a busca fuzzy ("borrada"): em vez de perguntar "é igual?", ela pergunta "quão parecido é?"

⚠️ Tente imaginar buscar "aplicativo de comida" e digitar sem querer "aplicatvo de comda" — uma busca 100% exata devolveria zero resultados, uma péssima experiência. É exatamente esse problema que a busca fuzzy resolve.

Fuzzy Search · A régua de diferença
🧩 Distância de Levenshtein: contando os passos até virar a outra palavra

A distância de edição (Levenshtein) conta o número mínimo de operações — inserir, remover ou substituir uma letra — necessárias para transformar uma palavra na outra. É tipo um jogo de "telefone sem fio" ao contrário: quantos passinhos até as duas palavras ficarem idênticas? Quanto menor a distância, mais parecidas as palavras são.

Fuzzy Search · Um outro jeito de comparar
🔤 N-gramas: comparando pedacinhos de 3 letras

Calcular Levenshtein para milhões de palavras a cada busca é caro. Uma alternativa popular (usada por índices como o pg_trgm do Postgres) é quebrar cada palavra em pedacinhos sobrepostos de 3 letras — os trigramas — e comparar quantos pedacinhos as duas palavras têm em comum. É como comparar dois quebra-cabeças: quantas peças são idênticas?

Busca Semântica · A grande virada
🗺️ O mapa do significado: o que é um embedding?

Imagine um mapa gigante onde cada palavra ou frase vira um pontinho. Palavras parecidas em significado ficam perto uma da outra nesse mapa; palavras diferentes ficam longe. Esse pontinho é o que chamamos de embedding — uma lista de números (coordenadas) que representa o "sentido" de um texto. Um modelo de IA aprende essas coordenadas lendo bilhões de frases: ele percebe que "cachorro" e "gato" aparecem em contextos parecidos ("meu ___ late", "meu ___ mia", ambos "animal de estimação"), então os coloca próximos no mapa.

🧠 Embeddings de verdade
Modelos reais (como os usados no Google, ChatGPT ou bibliotecas como sentence-transformers) usam de 384 a 3072 dimensões — coordenadas demais para desenhar! O mapa abaixo usa só 2 dimensões para caber na tela, só para você pegar a intuição.
📏 "Perto" = "parecido"
A mágica é que a distância no mapa vira uma medida de "quão parecido é o significado". Isso permite achar frases relacionadas mesmo que não compartilhem nenhuma palavra em comum — a base da busca semântica.

Busca Semântica · A régua do significado
📐 Similaridade de cosseno: medindo o ângulo entre significados

Para comparar dois embeddings, a busca semântica geralmente não mede a distância direto — ela mede o ângulo entre os dois vetores (as duas "setas" que saem da origem até cada ponto). Dois vetores apontando quase para o mesmo lugar têm ângulo pequeno → alta similaridade. Vetores apontando para lados opostos têm baixa (ou negativa) similaridade. Essa é a similaridade de cosseno, e ela vai de -1 (opostos) a 1 (idênticos).

O Melhor dos Dois Mundos
🔀 Busca híbrida: somando rankings com RRF

Por que escolher? A maioria dos sistemas modernos de busca roda a busca por palavra-chave e a busca semântica ao mesmo tempo, e depois funde os dois rankings em um só. Uma técnica simples e popular é o Reciprocal Rank Fusion (RRF): cada documento ganha uma pontuação igual a 1 / (k + posição) em cada lista, e as pontuações são somadas. Documentos bem colocados nas duas listas sobem ao topo.

Por que isso funciona tão bem

Se um documento é o 1º colocado nas duas listas, ele recebe a maior pontuação possível — um sinal muito forte de relevância. Se ele aparece bem em só uma lista (por exemplo, tem o significado certo mas não a palavra exata), ainda ganha uma pontuação relevante, sem depender 100% de nenhuma das duas técnicas sozinha.

Mão na Massa
💻 As três buscas, na prática

Dá para resolver quase tudo em SQL puro — full-text, fuzzy, vetorial e até a busca híbrida rodam direto no Postgres. Python só entra num único momento indispensável: gerar o embedding a partir do texto (o banco não sabe transformar frase em vetor sozinho).

SQL · Full-Text Search — buscar e ranquear (tsvector)
sqlcopiarSELECT titulo, ts_rank(busca, query) AS score FROM artigos, websearch_to_tsquery('portuguese', 'gato preto') query WHERE busca @@ query ORDER BY score DESC; -- 'busca' é uma coluna tsvector, já tokenizada e indexada (GIN)
SQL · Full-Text Search — índice GIN + busca por frase
sqlcopiarALTER TABLE artigos ADD COLUMN busca tsvector GENERATED ALWAYS AS (to_tsvector('portuguese', corpo)) STORED; CREATE INDEX idx_busca_gin ON artigos USING GIN (busca); -- phraseto_tsquery exige as palavras nessa ordem, lado a lado SELECT titulo FROM artigos, phraseto_tsquery('portuguese', 'gato preto') q WHERE busca @@ q;
SQL · Fuzzy Search — pg_trgm (trigramas)
sqlcopiarCREATE EXTENSION IF NOT EXISTS pg_trgm; SELECT nome, similarity(nome, 'cachoro') AS sim FROM animais WHERE nome % 'cachoro' -- % = "parecido o suficiente" ORDER BY sim DESC;
SQL · Fuzzy Search — distância de edição direto no banco
sqlcopiarCREATE EXTENSION IF NOT EXISTS fuzzystrmatch; SELECT nome, levenshtein(nome, 'cachoro') AS distancia FROM animais ORDER BY distancia ASC LIMIT 5; -- soundex compara pela "sonoridade" da palavra, não pelas letras SELECT nome FROM animais WHERE soundex(nome) = soundex('cachoro');
SQL · Busca Semântica — pgvector (tabela, índice e busca)
sqlcopiarCREATE EXTENSION IF NOT EXISTS vector; CREATE TABLE artigos ( id serial PRIMARY KEY, texto text, embedding vector(384) -- mesma dimensão do modelo usado ); CREATE INDEX ON artigos USING hnsw (embedding vector_cosine_ops); SELECT texto, 1 - (embedding <=> '[0.12,-0.04,...]') AS similaridade FROM artigos ORDER BY embedding <=> '[0.12,-0.04,...]' -- <=> = distância de cosseno LIMIT 5;
SQL · Busca Híbrida — full-text + vetor fundidos com RRF
sqlcopiarWITH busca_texto AS ( SELECT id, row_number() OVER (ORDER BY ts_rank(busca, q) DESC) AS rank FROM artigos, websearch_to_tsquery('portuguese', 'gato preto') q WHERE busca @@ q LIMIT 20 ), busca_vetor AS ( SELECT id, row_number() OVER (ORDER BY embedding <=> '[0.12,-0.04,...]') AS rank FROM artigos ORDER BY embedding <=> '[0.12,-0.04,...]' LIMIT 20 ) SELECT coalesce(t.id, v.id) AS id, coalesce(1.0/(60+t.rank), 0) + coalesce(1.0/(60+v.rank), 0) AS score_rrf FROM busca_texto t FULL OUTER JOIN busca_vetor v USING (id) ORDER BY score_rrf DESC LIMIT 10;
Python · Fuzzy Search fora do banco (rapidfuzz)
pythoncopiarfrom rapidfuzz import process, fuzz candidatos = ["gato", "cachorro", "cavalo", "galinha"] resultado = process.extract( "cachoro", candidatos, scorer=fuzz.ratio, limit=3 ) print(resultado) # [('cachorro', 93.3, 1), ...]
